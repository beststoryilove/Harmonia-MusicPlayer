## 1. 歌词元数据过滤误伤正文

- **根因**：旧判定按「任意子串命中角色词」（作词/作曲/编曲…）整行删除，正文里出现
  「作词」「出品」等词即被误杀；另有「歌名-艺人」整行形式规则散在两份实现里不一致。
- **修复**：判定核心迁移到 `js/lib/pure.js` 的 `HarmoniaLib.isCreditLine / isArtistCreditLine`
  （行首锚定 + 分隔符结构判定：`角色[:：]值`、`(OP&SP)：`、括号内署名等），
  两份 `main.js` 的 `filterLyricCredits` 全部委托 pure.js；pure 级测试 55 条覆盖典型误杀样本
  （如「谁设计的故事」「（OP&SP）xx」不误删、「（作词：xxx）」全角括号可识别）。
- **落点**：两份 `js/lib/pure.js`；两份 `js/main.js` `filterLyricCredits`。

## 2. 自定义顺序部分情况不生效

- **根因**（多处叠加）：
  1. `renderPlaylist` 直接 `sort()` 原数组引用，与队列索引互相踩踏；
  2. 顺序映射键混用数字/字符串 id，`orderMap.get(a.id)` 在 id 为字符串时永远 miss；
  3. 移动端拖拽只绑了 `mousedown` 链路，触屏无 `touchmove/touchend` → 排序手势失效；
  4. 删歌/清队列后 `customOrder` 不清理，出现悬空 id；
  5. 队列/顺序变化后**无缝预载仍指向旧下一首**，过渡时播放顺序与界面顺序不一致。
- **修复**：副本排序（`.slice()`）；`customOrder` 读写全链路 `String(id)` 归一；
  `syncCustomOrderWithList` 悬空清理；H 补 `touchmove(passive:false)/touchend/touchcancel`；
  新增共享 `resolveGaplessNext()` 统一「下一首」判定（自定义顺序/随机/会话一致），
  `updatePlaylistOrder`/会话打开与关闭后调 `syncGaplessPreloadAfterQueueChange()` 重新校验预载指向。
  H 端同步移植 `clearGaplessPreload/syncGaplessPreloadAfterQueueChange`。
- **验证**：`gapless-queue-sync`（11 场景）、`gapless-transition-fallback`、`smart-transition-pure` 全过。

## 3. 开屏图片偶发加载失败

- **根因**：单次 `fetch` 超时/网络抖动即放弃；http 页面下直接请求 https 图正常，但反之
  （https 页 + http 图 URL）被混合内容拦截；`sessionStorage.startupBgFetched` 在**发起**时就置位，
  失败后本次会话不再重试。
- **修复**：`tryFetchStartupBackground` 升级为「fetch(8s AbortSignal) → `new Image` 带
  `crossOrigin` 真实解码探测 → 成功才落 `backgroundImage` 并置 `startupBgFetched`」，
  失败自动重试 1 次（间隔 2s），http 页面按需升级 https；`requestIdleCallback` 兜底延后。
- **落点**：两份 `main.js` 开屏 IIFE（H ~6712、F ~7917）。

## 4. 3D 丽音与智能过渡不兼容

- **根因**：过渡/音量逻辑直接写 `audioPlayer.volume`；3D 丽音将元素挂进
  `MediaElementSource` 后**元素 volume 被 WebAudio 旁路**，音量表现为「拉了没反应」，
  且 B 通道（预载下一首）不在图内、淡入淡出听感断裂；首次手势未授权 AudioContext 时整条链失效。
- **修复**：统一双写层 `applyMasterVolume / stSetALevel / stSetBLevel`（元素 volume 与
  `stMixAGain/stMixBGain` 同步），两份 main.js 的全部音量写点（音量条 seek、键盘 ±5%、
  legacy crossfade 初始化/淡变/完成/清理、gapless 预载静音起步、ST 复位）改走双写；
  开屏即 `ensureSpatial3dAttach()` + 首次 `pointerdown/keydown` 自摘除手势重试 +
  `play` 事件兜底补挂；设置迁移白名单补 `spatial3dEnabled`（导出/导入不再丢）。
- **验证**：`smart-transition-crossorigin`（B 通道 CORS 探测/旁路）、`smart-transition-pure` 全过；
  审计脚本确认两份文件内已无旁路裸写 `audioPlayer(B).volume =`（双写层内部与启动初始化除外）。

## 5. PIP/桌面歌词胶囊背景导致歌词不可读

- **根因**：胶囊底取封面主色原亮度（`rgba(r,g,b,0.35)`）——浅色封面时白字压在亮底上直接消失；
  桌面歌词窗口 `updateTheme` 在封面模式用「平均亮度」定黑白字，亮封面配暗部场景仍不可读；
  隐藏/恢复路径不重放主题时文字回落到默认深色。
- **修复**：
  - `updatePipTheme`：文字恒白，玻璃底 RGB 亮度钳制 `L>82 → ×(82/L)`、alpha 0.45，
    边框/投影固定浅层（两份 main.js 的 PiP 模板 + 两处 pip-lyrics-pill CSS）；
  - 桌面歌词：封面底图上新增常驻暗纱 `.dlp-album-bg::after`（垂直 0.28–0.42 黑渐变），
    `updateTheme` 置 `__dlpThemeApplied` 标记，`updateLyrics` 在「有封面但未显式取色」时
    兜底强制白字+深描边（两份 main.js 内嵌 DLP 模板，App 端与网页端一致）；
  - DLP 黑白字阈值与网页端统一（`lightFg?70:175`）。
- **验证**：`dlp-template-syntax`（各平台模板语法合法）、`dlp-transparent`、`dlp-loop-sync` 全过。

## 6. 移动端背景图巨大锯齿

- **根因**：移动端背景走「56×56 小图 JPEG(0.72) 烘焙 + cover 全屏放大」，且移动端样式
  **不带任何模糊**（桌面才有 `blur(30px)`）→ 小纹理被放大 20 倍直接露出色块锯齿；
  另外缓存路径不传已加载 Image，烘焙退化为低质量分支。
- **修复**（App 端为主）：
  - `bakeBlurredBg`：56→**128×128**，两步降采样（先 64 再放大回 128）+ `ctx.filter='blur(3px)'`
    预模糊 + JPEG 质量 0.9；
  - `applyAmBackgroundStyles`：移动端滤镜 `blur(8px) brightness(0.6)`（原为纯 brightness），
    并 `image-rendering:auto` 阻断个别 WebView 的最近邻采样；
  - `applyAmBackgroundStyles(bgDiv, url, imgEl)` 增加第三参：`applyAlbumArtWithPreload`
    把已解码的 `preImg` 转发给全部 3 个背景调用点（缓存路径、正常路径、预取路径），
    非过渡/失败路径显式传 `null`，烘焙不再依赖二次加载。
- **网页端镜像**：两份 `css/base.css` 的 `.am-background` 增加 `image-rendering:auto` 静态兜底。
- **说明**：曾误判存在 `top:-110px` 出血规则与 `installMobileBgCss` 钩子，核对后确认两仓库
  CSS 本就是 `top:0;height:100%`，已撤销误注入的代码，保持运行时干净。

## 7. 尾部元数据不被过滤

- **根因**：旧实现带 `CREDIT_CUTOFF = 60s` 时间窗——只过滤 60 秒之前的行，尾部（60s 后出现
  或歌曲本身较短）的 `作词/作曲` 行全部漏网；且 KRC **缓存写入的是过滤后结果**，
  一旦在开关开启时缓存过，之后即使关闭开关数据也永久缺失（规则升级也无法回补）。
- **修复**：时间窗彻底取消（头尾一视同仁，纯结构判定见 #1）；KRC 缓存改为
  **存原始解析数据、读取时再过滤**（`setCachedLyrics(…, r)` + `filterLyricCredits(parsed)`），
  旧缓存同样兼容；`CREDIT_CUTOFF` 仅保留在迁移注释中说明行为变更。

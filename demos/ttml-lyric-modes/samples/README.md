# 示例 TTML

用于测试与演示。前三个为本项目编写，最后一个来自社区歌词库。

| 文件 | 来源 | 演示内容 |
|---|---|---|
| `duet.ttml` | 本项目编写 | 多声部对唱；同一 `<p>` 内换声部会被切分为独立行；中英混排空白处理 |
| `background-overlap.ttml` | 本项目编写 | `ttm:role="x-bg"` 背景人声（含自身逐字时序与翻译）；`<p>` 之间时间轴重叠 |
| `sidecar-ruby.ttml` | 本项目编写 | `iTunesMetadata` sidecar 翻译/音译；`tts:ruby` 假名注音；三种时间格式混用 |
| `real-3402223603.ttml` | [AMLL TTML DB](https://github.com/amll-dev/amll-ttml-db)（网易云 ID `3402223603`） | **真实社区歌词**：51 主行 / 7 对唱行 / 19 背景行，含 6 处时间轴重叠，峰值 4 行同时活跃 |

## 为什么保留真实样本

`real-3402223603.ttml` 是本项目开发中价值最高的测试数据 —— 它暴露了两个用自造样例
无法发现的真实缺陷：

1. **空白处理错误**：真实文件把词间空格写在 span 内部（`<span>When </span>`），
   而非 span 之间；早期实现按「含换行的空白 = 排版缩进」丢弃，导致英文歌词空格全丢
   （`When the hands` → `Whenthehands`）。
2. **背景歌词整条消失**：真实文件里背景行与其所属段落共享 `itunes:key`，
   早期用 `itunes:key` 作行身份标识，使背景行被「与主行同文本」判重逻辑过滤掉。

此外它证明了**重叠时间轴不是理论问题**：该文件实测有 34 对行区间重叠。
